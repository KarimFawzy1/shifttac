Tiki-Taka Attribute Combinations (v1)
=====================================
Reference for board generation and gameplay intersections.
Sources: docs/tiki-taka-toe-rules.md (§17), tool/etl/*, TikiRandomBoardGenerator.

Last updated: 2026-06-20 (pair stats from current ETL build)


1. Core validity rule (rules §17, lines 604–608)
-------------------------------------------------
A board is valid only if EVERY playable cell has at least one valid answer.

For each cell intersection:

    rowAttribute × columnAttribute

the database must contain at least 1 valid player who has BOTH attributes
(independently — they need not overlap in the same career spell).

Shipped default: min_intersection = 3 (medium). Easy = 5. Hard = 1 (manual QA).

A pair with player_count = 0 is FORBIDDEN and must never appear on a board.


2. Attribute types on the board
-------------------------------
Each 3×3 board has 3 row headers + 3 column headers (6 distinct attribute IDs).
Each of the 9 cells validates: player has row[r] AND col[c].

Type          ID prefix   v1 allowlist count   Examples
------------  ----------  -------------------  ---------------------------
Club          club:       100                  Liverpool, Real Madrid, Barcelona
Nation        nation:     48                   Brazil, Egypt, Argentina, France
League        league:     5                    GB1, ES1, IT1, L1, FR1
Position      pos:        4                    GK, DEF, MID, FWD

Deferred (not in v1 boards): Coach attributes.


3. Cell-level attribute-type combinations
-----------------------------------------
These are the TYPE pairs that can appear at a single cell (row type × col type).
Order does not matter for validation (club×nation = nation×club).

A) Shipped in ETL pre-generated boards (D10 templates)
   ----------------------------------------------------
   club × nation     Default recommended layout (rows = clubs, cols = nations)
   league × club     Alternate recommended layout (rows = leagues, cols = clubs)

   Example cells:
     Liverpool × Egypt        → Mohamed Salah
     GB1 × Barcelona          → players who appeared in PL and played for Barcelona
     Real Madrid × Brazil     → Brazilian players who played for Real Madrid

B) Also supported at runtime (TikiRandomBoardGenerator + attribute_pair_stats)
   ---------------------------------------------------------------------------
   club × club         Same-type; e.g. Liverpool × Chelsea → Salah
   league × league     Same-type; e.g. GB1 × ES1
   club × league       e.g. Liverpool × GB1
   club × position     e.g. Liverpool × FWD
   nation × club       (mirror of club × nation)
   nation × league     e.g. Brazil × GB1
   nation × position   e.g. Brazil × FWD
   league × position   e.g. GB1 × MID
   position × club     (mirror of club × position)
   position × nation   (mirror of nation × position)
   position × league   (mirror of league × position)

   Current pair-stats coverage (total pairs / pairs with count ≥ 3):
     club × club       4950 / 749
     club × nation     4800 / 583
     club × league      500 / 324
     club × pos         400 / 240
     league × nation    240 / 125
     league × league     10 /  10
     league × pos        20 /  20
     nation × pos       192 / 103

C) NOT displayed in v1 gameplay (forbidden by board layout rules)
   -------------------------------------------------------------
   nation × nation     Nation appears on at most ONE axis; no nation×nation cells
   position × position At most ONE position header on the entire board
   coach × *           Coaches deferred post-v1
   * × coach           Coaches deferred post-v1

D) Rejected at build time even if data existed
   --------------------------------------------
   Same attribute ID on both row and column (e.g. Liverpool × Liverpool)
   Any cell with player_count = 0
   Attributes outside v1 allowlists
   Boards where too many cells have only 1–2 obscure answers (below MIN_INTERSECTION)


4. Board layout templates (how headers are composed)
----------------------------------------------------

4a. ETL pre-generated boards (bundled in tiki_taka.db)
    Config: tool/etl/config/board_generation.yaml
    Generator: tool/etl/generate_boards.py

    Template ID     Row headers       Column headers    Selection weight
    -------------   --------------    ----------------  ------------------
    club_nation     3 clubs           3 nations         50%  (equal rng.choice)
    league_club     3 leagues         3 clubs           50%  (equal rng.choice)

    All 9 cells in these boards use only the cross-type pairs listed in §3A.
    Featured boards in featured_boards.yaml are hand-curated from these templates.

4b. Runtime random boards (fresh board each entry/restart)
    Generator: lib/features/tiki_taka/domain/services/tiki_random_board_generator.dart

    Each template defines how many of each type appear on rows vs columns.
    Format: (row: clubs, nations, leagues, positions | col: clubs, nations, leagues, positions)

    #   Row composition          Col composition          Weight   ~%
    --  ---------------------    ---------------------    ------   ----
    1   3 clubs                  3 clubs                  30       26.3%
    2   3 clubs                  1 nation + 1 league + 1 position   25   21.9%
    3   1 nation + 1 league + 1 position   3 clubs      25       21.9%
    4   2 clubs + 1 league       2 clubs + 1 league     12       10.5%
    5   2 clubs + 1 nation       3 clubs                  8        7.0%
    6   3 clubs                  2 clubs + 1 nation       8        7.0%
    7   3 clubs                  2 clubs + 1 league       6        5.3%
                                                    Total weight = 114

    Cell types produced by each runtime template:

    #1  club×club only (full club grid — most common)
    #2  club×nation, club×league, club×position
    #3  nation×club, league×club, position×club
    #4  club×club, club×league, league×club, league×league
    #5  club×club, nation×club
    #6  club×club, club×nation
    #7  club×club, club×league

    Layout constraints enforced at runtime:
      - At most 1 nation per axis (row or col)
      - At most 1 league per axis
      - At most 1 position on the entire board (row + col combined)
      - Nation on at most one axis (never nation rows AND nation cols)
      - No attribute ID repeated across both axes
      - All 9 cells must have player_count ≥ min_intersection (default 3)


5. Weights summary
------------------

WHAT IS WEIGHTED                          HOW
----------------------------------------  ------------------------------------------
Runtime board layout template             Integer weights in TikiRandomBoardGenerator
                                          (§4b table; total 114, rolled uniformly)

ETL auto board template                   Equal 50/50 between club_nation and league_club
                                          (rng.choice over templates list)

Individual clubs / nations / leagues      NOT weighted — uniform random pick from the
/ positions on a board                    viable pool (attributes that satisfy partner
                                          map and min_intersection threshold)

Specific attribute pair popularity        NOT weighted for board generation — viability
                                          only (player_count ≥ threshold)

Search result ordering                    Separate from boards — search_rank_boost.yaml
                                          and legendary_search_rank_boost.yaml affect
                                          player search, not which headers appear.

7. Difficulty vs intersection counts (rules §17)
------------------------------------------------
Difficulty is driven by the WEAKEST cell on the board (min of 9 player_counts).

  Easy     every cell ≥ 5 valid players
  Medium   every cell ≥ 3 valid players  (default ETL + runtime)
  Hard     every cell ≥ 1 valid player   (manual QA; pairs with 1–2 answers flagged risky)

ETL quality bands (build_attribute_pair_stats.py):
  player_count 0     Forbidden
  player_count 1–2   Risky — manual QA only
  player_count ≥ 3   OK for casual / medium
  player_count ≥ 5   Easy mode
  player_count ≥ 10  Ideal


8. Legendary players note
-------------------------
Legendary CSV ingest uses the same attribute IDs and intersection rules.
A legendary player appears in a cell only if they have BOTH row and column
attributes after ETL (club career, citizenship nation, league_club derivation,
position bucket). Players with fewer than 2 distinct attributes are excluded
from the database entirely (see legendary_players_plan.md).

Dual-nation exception: "Argentina / Spain" (Di Stéfano) maps to both
nation:argentina and nation:spain edges.


9. Quick reference — all valid v1 cell TYPE combinations
--------------------------------------------------------
Displayed in gameplay (when pair stats ≥ min_intersection):

  club      × club
  club      × nation
  club      × league
  club      × position
  nation    × club
  nation    × league
  nation    × position
  league    × club
  league    × league
  league    × position
  position  × club
  position  × nation
  position  × league

Not displayed:

  nation    × nation
  position  × position
  coach     × *
  *         × coach

Default product template (rules §30): Clubs × Nations.
Alternate ETL template: Leagues × Clubs.
Runtime play heavily favors club×club (weight 30/114 ≈ 26% of boards).

Board template weights
Runtime (TikiRandomBoardGenerator, total weight 114):

| 3 clubs × 3 clubs                           |   30   | 26% |
| 3 clubs × (nation + league + position)      |   25   | 22% |
| (nation + league + position) × 3 clubs      |   25   | 22% |
| (2 clubs + 1 league) × (2 clubs + 1 league) |   12   | 11% |
| (2 clubs + 1 nation) × 3 clubs              |   8    | 7%  |
